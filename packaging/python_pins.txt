# Gepinnter Python für den Windows-Installationsassistenten.
#
# Der Assistent lädt GENAU diese Datei von python-build-standalone (dieselbe
# Quelle, aus der sich auch `uv` bedient) und prüft sie gegen die hier
# hinterlegte Prüfsumme.  Die Prüfsumme reist damit MIT dem Paket — eine
# nebenher heruntergeladene .sha256-Datei deckte nur Übertragungsfehler ab,
# nicht eine ausgetauschte Quelle.
#
# Warum nicht `uv python install` wie unter Linux: uv legt zum Schluss einen
# Verweis auf die Nebenversion an (`python\cpython-3.12-…` → Vollversion), und
# das ist unter Windows ein JUNCTION.  Wo OneDrive „Dateien bei Bedarf" läuft,
# verweigert dessen Filtertreiber das Anlegen — os error 448,
# STATUS_UNTRUSTED_MOUNT_POINT, „der Pfad kann nicht durchlaufen werden, da er
# einen nicht vertrauenswürdigen Bereitstellungspunkt enthält" (astral-sh/uv
# #19616).  Abschalten lässt sich der Verweis nicht.  Der Assistent lädt das
# Archiv deshalb selbst; ausgepackt wird ein gewöhnliches Verzeichnis, und
# kein Reparse-Punkt entsteht.  doc/design/13_distribution.md §5.1.
#
# Die Nebenversion MUSS zu K1520_PY_VERSION (lib/common.sh) passen — sonst
# passen die Wheels aus requirements.lock nicht.  build_payload.sh prüft das.
#
# Aktualisieren:  packaging/build_payload.sh --refresh-python
#
# Geladen wird die Variante `install_only_stripped` — dieselbe, aus der sich
# auch uv bedient.  `install_only` bringt zusätzlich die Fehlersuchdateien
# (*.pdb) mit: 43 statt 21 MB Download und **190 statt 69 MB** ausgepackt.  Beim
# Anwender sind sie nutzlos, und sie sprengten den Größenwächter der CI (245 MB
# statt der erwarteten ~120, gemessen 2026-08-14).
#
# Format:  <Zieltripel> <Größe in Byte> <SHA256 des Archivs>
