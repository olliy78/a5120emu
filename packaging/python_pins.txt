# Gepinnter Python fuer den Windows-Installationsassistenten.
#
# Der Assistent laedt GENAU diese Datei von python-build-standalone (dieselbe
# Quelle, aus der sich auch `uv` bedient) und prueft sie gegen die hier
# hinterlegte Pruefsumme.  Die Pruefsumme reist damit MIT dem Paket — eine
# nebenher heruntergeladene .sha256-Datei deckte nur Uebertragungsfehler ab,
# nicht eine ausgetauschte Quelle.
#
# Warum nicht `uv python install` wie unter Linux: uv legt zum Schluss einen
# Verweis auf die Nebenversion an (`python\cpython-3.12-…` → Vollversion), und
# das ist unter Windows ein JUNCTION.  Wo OneDrive „Dateien bei Bedarf" laeuft,
# verweigert dessen Filtertreiber das Anlegen — os error 448,
# STATUS_UNTRUSTED_MOUNT_POINT, „der Pfad kann nicht durchlaufen werden, da er
# einen nicht vertrauenswuerdigen Bereitstellungspunkt enthaelt" (astral-sh/uv
# #19616).  Abschalten laesst sich der Verweis nicht.  Der Assistent laedt das
# Archiv deshalb selbst; ausgepackt wird ein gewoehnliches Verzeichnis, und
# kein Reparse-Punkt entsteht.  doc/design/13_distribution.md §5.1.
#
# Die Nebenversion MUSS zu K1520_PY_VERSION (lib/common.sh) passen — sonst
# passen die Wheels aus requirements.lock nicht.  build_payload.sh prueft das.
#
# Aktualisieren:  packaging/build_payload.sh --refresh-python
#
# Geladen wird die Variante `install_only_stripped` — dieselbe, aus der sich
# auch uv bedient.  `install_only` bringt zusaetzlich die Fehlersuchdateien
# (*.pdb) mit: 43 statt 21 MB Download und **190 statt 69 MB** ausgepackt.  Beim
# Anwender sind sie nutzlos, und sie sprengten den Groessenwaechter der CI (245 MB
# statt der erwarteten ~120, gemessen 2026-08-14).
#
# Format:  <Zieltripel> <Groesse in Byte> <SHA256 des Archivs>
