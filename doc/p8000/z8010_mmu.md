## 1. Aufbau

- Eine MMU verwaltet **64 Segmente** (eine Hälfte der 128 Segmentnummern der U8001). Je Segment
  ein **Segment-Deskriptor-Register (SDR)**, 32 Bit = 4 Bytes: `BAH, BAL, LIMIT, ATTR`
  (Reihenfolge = Zugriffsreihenfolge, DSCR 0…3). [TB §2.2.1, §3.1, Bild 3.1, D.1; Z S. 563] — bestätigt.
- Dazu **3 Steuerregister** (MR, SAR, DSCR, je 8 Bit) und **6 Statusregister** (VTR, VSN, VOFF,
  BCSR, ISN, IOFF, je 8 Bit). [TB §3.0] — bestätigt.
- Gespeichert wird nur das **obere Byte** des Offsets (VOFF/IOFF); das untere Byte liefert externe
  Hardware (P8000: TRPL/IF1L, `doc/p8000/schaltplan_16bit.md` §4). [TB §3.3.1/3.3.2] — gelesen.
- Übersetzt werden **nur Speicherzyklen** (Status %8, %9, %A, %B, %C, %D); Standard-E/A,
  interne Operationen, Refresh werden ignoriert, Spezial-E/A (%3) nur als Befehl bei aktivem /CS.
  [TB §2.1, Tab. 2.1, §4.1] — bestätigt (Z S. 562–566).
- Adresse: 7-Bit-Segmentnummer SN0–SN6 + 16-Bit-Offset → 24-Bit-physisch (A0–A23); die MMU
  liefert nur **A8–A23**, A0–A7 gehen am Chip vorbei direkt aus dem Offset. [TB §2.1.1, §4.2] — bestätigt.

## 2. Segment-Deskriptor

**Basisfeld** (BAH:BAL, 16 Bit) = physische Anfangsadresse Bits 23…8; Bits 7…0 sind 0
(Granularität 256 B). [TB §3.1.1] — bestätigt.

**Limitfeld N** (8 Bit) = Anzahl 256-Byte-Blöcke: DIRW = 0 → **N+1** Blöcke, erlaubter Offset
`0 … 256·N+255`; DIRW = 1 → **256−N** Blöcke, erlaubter Offset `256·N … 65535`. Verglichen wird
das **obere Offset-Byte** gegen N. [TB §3.1.2, §5.4; Z S. 562/563] — bestätigt.

**Attributfeld** (Bit 7…0): `REF CHG DIRW DMAI EXC CPUI SYS RD` [TB Bild 3.1, D.2; Z Bild 6] — bestätigt
(auch `mmu.h`, **oktal**: RD 01, SYS 02, CPUI 04, EXC 010, DMAI 020, DIRW 040, CHG 0100, REF 0200 — [W]).

| Bit | Flag | Wirkung [TB §3.1.3] |
|---|---|---|
| 0 | RD | nur lesen; Schreiben → RDV. Befehlsholen aus RD-Segment erlaubt |
| 1 | SYS | nur Systemmode; Zugriff mit **N/S = High** → SYSV |
| 2 | CPUI | CPU gesperrt (auch für den laufenden Prozess sofort); nur DMA darf → CPUIV |
| 3 | EXC | nur Befehlsholen (Status %C/%D); sonst → EXCV |
| 4 | DMAI | DMA gesperrt (nur CPU); DMA-Zugriff → Suppress, kein Trap, kein VTR-Flag |
| 5 | DIRW | Stacksegment: wächst abwärts von Offset 64K; Schreiben in den untersten Block → Warnung (ohne Suppress) |
| 6 | CHG | wird **automatisch** gesetzt bei Schreibzugriff **der CPU** ohne Violation |
| 7 | REF | wird automatisch gesetzt bei jedem Lese-/Schreibzugriff **der CPU** ohne Violation |

DMA-Zugriffe setzen weder CHG noch REF. [TB §7.1] — gelesen.

**Stacksegment anlegen** [TB §5.4, Bild 5.3/5.4]: `Basis = %FF00 + TOP`, `Limit = %100 − n`
(TOP = 256-Byte-Block der höchsten Adresse + 1, n = Blockzahl). Die Basisaddition **wrappt auf
24 Bit** („Umrunden des Speichers“: Adresse %FFFFFF ist von %000000 gefolgt); so liegt ein Stack in
den untersten 64 KB, obwohl die Basis „negativ“ ist. Beispiel [TB]: TOP=8, n=4 → Basis %FF08, Limit
%FC, Offset %FFE0 → physisch %7E0. — bestätigt (WEGA nutzt es, §7).

## 3. Steuer- und Statusregister

### 3.1 Bitbelegung (alle bestätigt: [TB Bild 3.4/3.5/D.3/D.4], [Z Bild 7/8], [M z8010.h])

```
MR   (Befehl 00)  7 MSEN | 6 TRNS | 5 URS | 4 MST | 3 NMS | 2..0 ID
SAR  (Befehl 01)  5..0 Deskriptornummer (7..6 = 0)
DSCR (Befehl 20)  1..0 DSC: 0=BAH 1=BAL 2=LIMIT 3=ATTR (7..2 = 0)
VTR  (Befehl 02)  7 FATL | 6 SWW | 5 PWW | 4 EXCV | 3 CPUIV | 2 SLV | 1 SYSV | 0 RDV
VSN  (Befehl 03)  6..0 Segmentnummer (7 = 0)
VOFF (Befehl 04)  7..0 Offset High
BCSR (Befehl 05)  5 N/S | 4 R/W | 3..0 Status ST3..ST0   (7..6 = 0)   ! Pegel: N/S=1 Normal, R/W=1 Lesen
ISN  (Befehl 06)  6..0 Segmentnummer (7 = 0)
IOFF (Befehl 07)  7..0 Offset High
```

Gegenprobe der Bitlagen: [TB §8.1.2] VTR = %05 ⇒ SLV+RDV; BCSR = %28 ⇒ N/S=1 (Normal), R/W=0
(Schreiben), Status 8 (Datenzugriff). [W] `pwwarn` prüft **VTR-Bit 5 = PWW**. [W] MON16 testet MR-Werte
%D0/%D1/%D2 (= MSEN, TRNS, MST, NMS = 0, ID = 0/1/2).

### 3.2 Modus-Register

- **MSEN** = 0: Adressausgänge Tri-State, alle anderen MR-Flags ignoriert (Segmentschutz aus). [TB §3.2.3]
- **TRNS** = 0 (bei MSEN = 1): **keine Übersetzung**, keine Rechteprüfung; Ausgabe `A8–A15 = AD8–AD15`,
  `A16–A22 = SN0–SN6`, **A23 = 0**; URS/MST/NMS werden ignoriert. [TB §3.2.3, §4.1 Nr. 3, §7.2.1]
- **URS** muss dem Segmentnummernbit **SN6** entsprechen, sonst Tri-State (kein Zugriff). [TB §3.2.3, §4.1 Nr. 4]
- **MST**/**NMS**: ist MST = 1, übersetzt die MMU nur, wenn der **N/S-Eingang = NMS** (N/S High ⇔ NMS = 1).
  Sonst Tri-State. MST = 0: N/S wird nicht verglichen. [TB §4.1 Nr. 5, §7.3.2]
- **ID** (3 Bit): wählt die AD-Leitung beim Segmenttrap-Anerkennungszyklus (§6.3).
- Prioritätsfolge der Freigabe [TB §4.1]: Speicherzyklus → MSEN → TRNS → URS=SN6 → (MST ⇒ NMS=N/S).

### 3.3 SAR und DSCR

- SAR zeigt auf einen der 64 SDR; **autoinkrement** bei den Befehlen %0C–%0F, **Nummer 63 → 0 (Umlauf)**.
  [TB §3.2.1, §6.2.13] — gelesen. ([M] sättigt bei 63 — Abweichung, §9.)
- DSCR zählt das Byte im SDR. Beim Basisfeld-Befehl (%08/%0C) und den Gesamtbefehlen (%0B/%0F) **fasst
  die MMU das DSCR zu Beginn nicht an** (Fortsetzung nach Unterbrechung eines Blockbefehls); der
  Anwender muss es vorher auf 0 stellen. Bei Limit-/Attributbefehlen (%09/%0A/%0D/%0E) setzt die MMU
  das DSCR selbst auf 2 bzw. 3. Nach **korrektem** Ende (alle 2 bzw. 4 Bytes) ist DSCR wieder 0; wird
  nach einem Byte abgebrochen, bleibt es auf 1 stehen. [TB §3.2.2, §7.4, §6.2.9–6.2.16] — gelesen.
- Schreiben des SAR setzt das DSCR in [TB] **nicht** ausdrücklich auf 0 (nur [M] tut das, §9).

## 4. Spezial-E/A-Befehle (die „Programmierschnittstelle“)

### 4.1 Zyklus und Adresswort [TB §6.1, B.2, Bild 6.1/6.6/B.3; Z S. 566]

- Status ST3–ST0 = **%3 (0011)**, N/S = Low (Spezial-E/A ist privilegiert). Die MMU nimmt einen Befehl
  nur bei **aktivem /CS** an.
- Das Befehlswort ist die 16-Bit-E/A-Adresse: **`AD15–AD8` = Befehlscode**, **`AD7–AD0` = Auswahlcode**
  (nur das für /CS dekodierte Byte; **Bit 0 = 0**, Byteübertragung auf gerader Adresse, Daten im
  **hohen** Byte AD8–AD15). Der Befehlscode liegt in T1 an AD8–AD15 (steigende Flanke /AS), die
  Daten in T3; zwischen T2 und T3 ein automatischer Wartetakt (TWA).
- Lesen: Daten stehen nach TWA auf AD8–AD15 (Ausgabe bei /DS Low); Schreiben: Daten am Ende T2 gültig.
- Ein Wortbefehl (SIN/SOUT) überträgt nur das **hohe Byte**; das niedere ist „nicht spezifiziert“
  (Bild C.2) — Byte-Befehle sind der Normalfall.
- Befehle ohne Daten (Setzen/Rücksetzen): Quelle beliebig (Register wird ausgegeben, aber ignoriert).

### 4.2 Befehlscodes (Tab. 6.2/E.3; Z S. 566; alle bestätigt außer %10, s. u.)

| Code | Wirkung | Dir. | Bytes |
|---|---|---|---|
| %00 | Modus-Register MR | R/W | 1 |
| %01 | Segment-Adress-Register SAR | R/W | 1 |
| %20 | Deskriptor-Selektor-Counter DSCR | R/W | 1 |
| %02 | VTR | R | 1 |
| %03 | VSN | R | 1 |
| %04 | VOFF | R | 1 |
| %05 | BCSR | R | 1 |
| %06 | ISN | R | 1 |
| %07 | IOFF | R | 1 |
| %08 | Basisfeld des SDR[SAR] (erst High-, dann Low-Byte) | R/W | 2 |
| %09 | Limitfeld (DSCR := 2) | R/W | 1 |
| %0A | Attributfeld (DSCR := 3) | R/W | 1 |
| %0B | gesamter SDR in Reihenfolge BAH, BAL, LIMIT, ATTR | R/W | 4 |
| %0C | wie %08, danach SAR := SAR+1 (DSCR zurück auf 0 je Deskriptor) | R/W | 2 |
| %0D | wie %09, danach SAR+1 | R/W | 1 |
| %0E | wie %0A, danach SAR+1 | R/W | 1 |
| %0F | wie %0B, danach SAR+1 | R/W | 4 |
| %10 | **Reset**: MR, VTR, DSCR := 0 (wirkt wie Hardware-Reset, **ohne** das CS-Sonderverhalten) | W | 0 |
| %11 | VTR := 0 | W | 0 |
| %13 | SWW-Flag im VTR löschen | W | 0 |
| %14 | FATL-Flag im VTR löschen | W | 0 |

| %12, %17–%1F, %21–%FF | reserviert („nicht benutzen“) | | |

- **%10 steht nur in [TB]** (§6.2.17, Tab. 6.2), **nicht** in der Zilog-Befehlsliste [Z S. 566] (dort
  „neun Befehle“ auf die Statusgruppe: %02–%07, %11, %13, %14) und auch nicht in [M]. WEGA/MON16 benutzen
  ihn nicht (sie schreiben MR := 0 mit %00). → **offen**, ob der Zilog-Baustein ihn kennt; der Emulator
  darf ihn wie [TB] ausführen (harmlos).
- %15/%16 **setzen** die Flags, die Datenbyte wird ignoriert [TB §6.2.21/22; Wortlaut „ohne Daten“].
  [M] weicht ab (löscht bei Daten = 0, §9) — WEGA ruft `soutb DATA_MMU+%1500, rh0` mit beliebigem rh0.
- Lesen/Schreiben von nicht benutzten Codes: [TB] schweigt; [M] liefert 0xFF bzw. ignoriert. → **offen**.
- Die CPU-Befehle (`SIN/SINB`, `SOUT/SOUTB`, `SIND/SINI/SOUTD/SOUTI` je mit `B` und `R`-Wiederholung
  `SINDR/SINIR/SOTDR/SOTIR`) [TB Tab. 6.1]: 12 Takte für Einzelbefehl, 21 für Block-Einzelschritt,
  **11 + 10·n** für die wiederholenden. Beim wiederholenden Befehl steht der Befehlscode im
  Register des E/A-Operanden (`ld r1,#CODE_MMU+%0B00; sotirb @r1,@rr2,r0`); er wird **bei jedem Byte
  erneut** ausgegeben, die MMU führt über DSCR/SAR selbst Buch. Unterbrechbar zwischen den Bytes —
  deshalb DSCR sichern (§3.3). — bestätigt ([W] `mch.s`, `mmu3b`).

## 5. Adressübersetzung

[TB §4, Bild 4.1–4.4; Z S. 562, Bild 4]

```
bedingt: Statuscode ∈ {%8..%D} ∧ MSEN ∧ (TRNS ∨ Durchreichen §3.2) ∧ URS == SN6
         ∧ (¬MST ∨ NMS == N/S)
sdr   = SDR[SN5..SN0]
phys[23..8] = (sdr.base16 + offset_hi8) mod 2^16       ! 16-Bit-Addition, kein 24-Bit-Übertrag
phys[7..0]  = offset_lo8                                ! unberührt
```

Der Überlauf der 16-Bit-Addition wird verworfen (⇒ die 24-Bit-Adresse „umrundet“, §2). Segmentnummer
und Offset werden zu **verschiedenen Zeiten** gelesen: SN0–SN6 eine Taktperiode **vor** AS (müssen in der
2. Hälfte von Tn gültig sein), Offset High mit /AS in T1; **A8–A23 gültig bis Ende T3**. Die
Segmentnummer ist 7 Bit — SN6 wählt die MMU als Ganzes, SN0–SN5 den SDR. (Beispiel [TB] Bild 4.3:
Segment 5, Basis %2311, Offset %1528 → %232628.) — bestätigt.

**Prüfung parallel zur Rechnung** [TB §2.1.1, §5.1, §5.4]:
1. Attribut gegen Status/N-S/R-W/DMA (siehe §6).
2. **Limit**: DIRW = 0: Offset-High **> N** → SLV. DIRW = 1: Offset-High **< N** → SLV.
3. **Schreibwarnung**: DIRW = 1 und Offset-High **= N** (unterster erlaubter Block, 256 B) bei
   **Schreibzugriff** → PWW/SWW/FATL laut §6.2, **ohne** Suppress.
4. Die physische Adresse wird **auch bei Violation ausgegeben** (nur /SUP schützt den Speicher). [TB §2.1.1]

**Richtung des Wachstums:** DIRW = 0 → Segment wächst vom Offset 0 aufwärts; DIRW = 1 → abwärts von
Offset 65535 (Stack; Befehle PUSH/CALL der Z8001 arbeiten abwärts). [TB §5.4]

**Nicht ausgeführt** (Ausgänge Tri-State, **kein** SUP, **kein** SEGT, keine Registeränderung): Zyklus
nicht in %8…%D; MSEN = 0; URS ≠ SN6; MST ∧ NMS ≠ N/S. Das ist der normale Zustand der „anderen“ MMUs
bei Mehrfachaufbau. [TB §2.1, §4.1, §7.3.1] — gelesen; **Folge** (Violation entsteht in einer nicht
ausgewählten MMU nicht) ist abgeleitet, wird aber durch §7.3.1 („keine Adressausgabe“) gestützt.

## 6. Verletzungen, Warnungen, SUP und SEGT

### 6.1 Verletzungsarten [TB §5.1, §3.3.4; Z S. 564]

| VTR | Name | Bedingung (CPU-Zugriff) |
|---|---|---|
| bit 0 RDV | Read-only | R/W = Low (Schreiben) auf Segment mit RD |
| bit 1 SYSV | System | N/S = High (Normalmode) auf Segment mit SYS |
| bit 2 SLV | Segmentlänge | Offset-High außerhalb Bereich (§5) |
| bit 3 CPUIV | CPU-Inhibit | **irgendein** CPU-Zugriff auf Segment mit CPUI |
| bit 4 EXCV | Execute-only | Zugriff **ohne** Status %C/%D auf Segment mit EXC |
| (kein Bit) | DMAI | DMA-Zugriff auf DMAI-Segment: nur SUP |
| bit 5 PWW | Primäre Schreibwarnung | Schreiben in untersten Block eines DIRW-Segments, VTR sonst leer |
| bit 6 SWW | Sekundäre Schreibwarnung | siehe §6.2 |
| bit 7 FATL | fatal | siehe §6.2 |

Mehrere Verletzungen **eines** Befehls setzen mehrere Flags gleichzeitig (Beispiel [TB §8.1.2]: Schreiben
auf <65>%9328 in RD-Segment mit Limit überschritten → VTR = %05). Bei Segmentnummern: VSN trägt die
**6-Bit-Nummer innerhalb der MMU** (Segment 65 → VSN = %01). VOFF = Offset High.

### 6.2 Zustandsautomat (Anhang A; §5.2, §3.3.4)

Primärflags `PRIME` = PWW ∨ EXCV ∨ CPUIV ∨ SLV ∨ SYSV ∨ RDV. Fünf Zustände:

| Zustand | FATL | SWW | PRIME |
|---|---|---|---|
| Normal | 0 | 0 | 0 |
| einfache Violation | 0 | 0 | 1 |
| SWW | 0 | 1 | 1 |
| FATL | 1 | 0 | 1 |
| SWW/FATL | 1 | 1 | 1 |

Übergänge [TB A.1–A.2.4, §5.2, §5.6] (je Befehl höchstens **ein** Zustandswechsel):

- Normal → einfach: **jede** Violation oder Schreibwarnung (Primärflags setzen, VSN/VOFF/BCSR/ISN/IOFF
  festhalten, SEGT ziehen, bei Violation SUP).
- einfach → SWW: Schreibwarnung durch einen **Systemstack-Zugriff** (Status %9, N/S = Low) bei bereits
  gesetztem Primärflag. SEGT wird gezogen, **kein SUP**; danach lösen weitere Systemstack-Schreibwarnungen
  **nichts** mehr aus (Schutz gegen Endlosschleife in der Trap-Routine).
- einfach/SWW → FATL bzw. SWW/FATL: **weitere Violation** (in einem *späteren* Befehl), oder
  Schreibwarnung im **Normalmode**, oder Systemmode-Schreibwarnung **ohne** Stackstatus %9.
- FATL (mit oder ohne SWW): weitere Violationen → **SUP, aber kein SEGT** und **keine** Flag-/Registeränderung;
  im SWW/FATL-Zustand lösen Schreibwarnungen **weder SEGT noch SUP** aus.
- Rückwege: Befehl %11 oder %10 oder Hardware-Reset → Normal; %13 löscht SWW; %14 löscht FATL
  (jeweils Zustand eine Stufe zurück).
- **Gleicher Befehl** erzeugt kein FATL/SWW aus eigenen Mehrfachverletzungen (§5.1/5.2); die Grenze
  „Befehl“ erkennt die MMU nur über die Statuscodes — **wie genau (Status %D als Befehlsanfang?)
  steht nicht in [TB]**. → **offen**, Hinweis: [M] kennt keine Befehlsgrenze (jede zweite Violation bei
  gesetztem VTR → nur FATL).

### 6.3 Wann SEGT, wann SUP [TB §5.3 Tab. 5.1, B.1; Z S. 565]

| | CPU-Zugriff | DMA-Zugriff |
|---|---|---|
| Violation | **SEGT + SUP** | nur **SUP** |
| Schreibwarnung | nur **SEGT** | kein Signal |

- **SUP** (Open-Drain, low-aktiv) in **T2** (Mitte) aktiv, **endet mit T3**; wird für **jeden weiteren
  CPU-Speicherzugriff bis zum Befehlsende** erneut ausgegeben („Suppress wird für diesen Zugriff und alle
  folgenden Zugriffe des Befehls ausgesendet“; dazwischenliegende DMA-Zyklen werden nicht unterdrückt,
  solange sie nicht selbst verletzen). Bei **DMA** nur für den eigenen Zyklus.
- **SEGT** (Open-Drain) in **T2**, bleibt Low bis zur Trap-Anerkennung (Status %4); weitere Violationen
  vor der Anerkennung werden trotzdem erkannt und behandelt.
- SUP wird **nie** bei Schreibwarnungen ausgegeben (der Stackeintrag darf passieren).
- **DMA ändert kein Statusregister** (auch nicht bei Violation; die DMA-Einheit muss selbst per SUP
  die Information sichern) und löst nie SEGT aus. [TB §3.3, §7.1]
- „**Unechter Befehlsholezyklus**“ [TB A.3, §5.5]: die CPU holt nach dem verletzenden Befehl noch das
  erste Wort des Folgebefehls und bricht ab, sobald sie den Trap anerkennt. Eine Violation in diesem
  Holzyklus erzeugt **SUP, aber kein SEGT und keine Flag-/Zustandsänderung**; ohne Violation kein SUP.
  Der Befehl wird nach Rückkehr neu geholt.

### 6.4 Statusregister: wann geschrieben (gelesen: [TB §3.3, §2.1.1], Gegenprobe [M])

- Bei der **ersten** Verletzung (nur CPU): VTR-Flags, VSN, VOFF, BCSR (Zustand des Verletzungszyklus). Die
  Register **frieren** bis zum Rücksetzen des VTR ein (nur die erste Verletzung wird festgehalten).
- **ISN/IOFF** = Adresse (Segment + Offset High) des **ersten Wortes des letzten erfolgreich begonnenen
  Befehlsholezyklus** (Status %D) **vor** der Verletzung. Liegt die Verletzung im Befehlsholen selbst,
  steht dort noch der **Vorgängerbefehl** (die Sprung-/Aufrufanweisung). [TB §3.3.2] — gelesen.
  [M] bildet das mit einem mitlaufenden `if1`-Latch nach; die genaue Taktphase des Einfrierens
  (Zeitpunkt der Aufnahme) ist in [TB] nicht angegeben → offen.
- BCSR [TB §8.1.2, Bild 3.5; M]: gespiegelt werden die Pegel der Leitungen — **N/S = 1 bei Normal, R/W = 1
  bei Lesen** (Systemmode-Schreiben liest sich also `0x08`, nicht `0x38`).
- REF/CHG nur ohne Verletzung und nur durch die CPU (§2).

### 6.5 Segmenttrap-Anerkennung [TB §5.5, §5.6, B.3, Bild 5.5–5.7; Z S. 565]

- Die Z8001 behandelt SEGT als Interrupt (Priorität: unter NMI, über VI/NVI, unter internen Traps).
  Nach Befehlsende: abgebrochener (scheinbarer) Befehlsholezyklus → **Anerkennungszyklus** Status **%4**
  mit **5 automatischen Wartetakten**; die MMU nimmt SEGT zurück.
- Alle MMUs mit **MSEN = 1** treiben AD(8+ID): **High** bei der MMU, die angefordert hat, **Low** bei den
  übrigen aktiven; Leitungen ohne aktive MMU bleiben Tri-State. Die CPU liest `AD0–AD15` als **Kennwort**
  und rettet es als erstes Wort auf den **Systemstack** (Reihenfolge von unten: PC-Offset, PC-Segment,
  FCW, Kennwort; das **Low-Byte des Kennworts ist undefiniert**). Bestätigt [W] `p.test.s`
  `SEGMENT_TRAP`: `and r2,#7` auf das High-Byte, Bit 0/1/2 = CODE/DATA/STACK (ID 0/1/2).
- Ein Befehl kann mehrere MMUs gleichzeitig verletzen ⇒ mehrere Kennwortbits.
- Beim Retten des Programmstatus erzeugt die MMU **kein** SUP, außer es liegt eine Violation vor; eine
  Schreibwarnung dabei → SWW (siehe §6.2). Das Wartezyklus-/TWA-Verhalten ist nur CPU-Seite.

## 7. Zusammenspiel mehrerer MMUs

### 7.1 Allgemein [TB §7.3, §8]

- **128 Segmente = 2 MMUs** (URS = 0 für 0…63, URS = 1 für 64…127). Mit nur einer MMU liefert ein
  Zugriff im anderen Bereich **keine Adresse und keinen Trap**; dafür braucht es externe Logik.
- **Mehrere Tabellen** (MST = 1 in allen MMUs): der /N/S-Eingang wird mit dem NMS-Flag verglichen; die
  Hardware darf N/S **frei treiben** („Spezial-Hardware, die die CPU-Statusleitungen überwacht und den
  N/S-Eingang der MMU steuert“) — es muss nicht der CPU-Mode sein. Taskumschaltung durch Setzen/
  Löschen von **MSEN** je MMU statt Umladen der SDR (§8.2 [TB]: 16-MMU-Beispiel, ID 0/1 System, 2/3 Tasks).
- **/CS** wählt die MMU bei Spezial-E/A; die Dekodierung ist **Systemsache** (Beispiel [TB]: AD1…AD7
  direkt, low-aktiv, **mehrere gleichzeitig** wählbar, z. B. `%F8` = beide MMUs). Während der
  **Adressübersetzung wird /CS ignoriert**.
- **DMASYNC** = High im CPU-Zyklus; Low bei DMA (SN ungültig) und High-Puls bei gültigem DMA-SN
  (Bild 7.1/B.1). Fester Pegel High = „es gibt nur CPU“. [TB §2.3.5, §7.1; Z S. 566]

### 7.2 Der P8000 (Schaltplan P2b §1; gegengeprüft an [W])

- Drei UB8010: **/CS = LAD1 (Code, `%FC`), LAD2 (Data, `%FA`), LAD3 (Stack, `%F6`)**, alle drei `%F0`.
  Die Befehlsnummer liegt in AD8–15 (`%0100` SAR, `%0B00` SDR, `%0800` Basis, `%1100` Reset VTR,
  `%1500` CPUI setzen, `%0200–%0700` Status). — bestätigt ([W] `mch.s` Konstanten, [P2b]).
- **N/S-Eingang jeder MMU = ihr Auswahlsignal** (MCODE−/MDATA−/MSTACK−, Bl. 5): die gewählte MMU sieht
  **N/S = Low**, die anderen High. **Mode-Register D3 = %1101 0011** = MSEN, TRNS, URS = 0, **MST = 1,
  NMS = 0**, ID = 3 ⇒ „übersetze nur, wenn dein N/S-Eingang Low ist“ — bestätigt: [W] `mch.s` `start`
  schreibt %D3 in die Stack-MMU; `p.test.s` schreibt %D0/%D1/%D2 in Code/Data/Stack. **Folge:** das
  SYS-Attribut wird gegen dieses *hardwareseitig erzeugte* N/S geprüft, nicht gegen den CPU-Mode
  (siehe [P2b] §1.4). Data-/Stack-MMU haben **SN6 fest Masse** ⇒ URS = 0.
- **MON16 `ENTRY_`**: `sout ALL_MMU, r3` mit r3 = 0 (MR := 0, MMUs abgeschaltet). Kernstart
  ([W] `mch.s` `start`): SAR := %3E, SDR %3E der **Code-MMU** := `{Basis = _kclicks+10−%100, Limit %F5,
  Attr %22 (DIRW|SYS)}` (Kernel-Stack-Segment, abwärts, unterste Adresse = `%F600`), dann MR der
  **Stack**-MMU := %D3. (Wo MR von Code-/Data-MMU im Kern gesetzt wird, ist in `mch.s` nicht
  zu sehen — vom Monitor vorbereitet? → **offen**.)
- Sonderfälle der Software: Segment %3B zeigt den User-Bereich über die Code-MMU (`mmu3b`: SDR aus
  Data-/Stack-MMU lesen, alle Attribute außer CPUI/DIRW löschen, in SDR %3B der Code-MMU schreiben);
  `invsdrs` = Befehl %15 an Data- und Stack-MMU; `resmmu` = %11 an alle drei; Trap-Auswertung liest VTR
  (%02), BCSR (%05), VSN (%03), VOFF (%04), ISN (%06), IOFF (%07) der auslösenden MMU, das untere
  Offset-Byte aus `TRAP_LOW` (E/A FFF1H), PC-Low aus `TRAP_PC_LOW` (FFF9H). — [W] gelesen.
- **Reset und /CS** [TB §7.2.1]: ist /CS **während /RESET** aktiv, wird MSEN gesetzt und TRNS gelöscht
  (Durchreichmodus für den Anfangslader). Ob die P8000-Verdrahtung das nutzt (/CS = LAD1…3 ist beim
  Reset hochohmig/undefiniert), ist **offen** — MON16 stellt sein Verhalten ohnehin selbst her.

## 8. Timing (nur soweit für die Emulation relevant)

- **Translation kostet keinen Wartetakt**: A8–A23 gültig ab Mitte T1 (≤ 175 ns nach gültigem Offset,
  ≤ 255 ns nach C↑), bis Ende T3 gültig; SEGT/SUP in T2. [TB Bild 4.4, Tab. B.1 Nr. 25/29/30–33; Z Bild 9/10].
  Das Hardwarehandbuch bestätigt „mit MMU ohne Wait-Zyklen“ (`hw_16bit.md` §5).
- Spezial-E/A-Zyklus: ein **Wartetakt TWA** zwischen T2 und T3 (CPU-seitig). Befehlsdauer s. §4.2.
- Segmenttrap-Anerkennung: **5 Wartetakte** (CPU-seitig). [TB §5.5]
- Taktgrenzwerte [TB Tab. B.1]: Tcc ≥ 250 ns (4 MHz), t_WCH/t_WCL ≥ 105 ns. Rest für die Emulation
  unerheblich.

## 10. Lücken (für P9a/P9b)

1. **Befehlsgrenze für FATL/SWW**: Wie erkennt die MMU „späterer Befehl“? [TB] A.3 spricht von „Befehlsholezyklus“
   und „Zustandswechsel je Befehl“; ein Status %D (erstes Wort) als Marke ist **abgeleitet**, nicht belegt.
2. **Befehl %10 Reset** (nur [TB]), unbenutzte Befehlscodes lesen/schreiben (Rückgabe, Wirkung): **nicht gefunden**.
3. **Einfrierzeitpunkt** von ISN/IOFF/VSN/VOFF innerhalb des Zyklus; ob eine zweite, nicht-fatale
   Violation (andere MMU/anderer Befehl) die Register überschreibt: laut [TB] nein („nur erste“), [M] ebenso.
4. **P8000-spezifisch**: /CS-Zustand bei /RESET (Durchreichmodus!), CODE-/DATA-MMU-MR im Kernstart,
   Verhalten **Hardware-Reset der MMU im P8000** (MRESET−) — [P2b]; Messung am Gerät nötig (Frage A2 in `quellen.md`).
5. **Seiten 11–17 des Zilog-PDF** (Pinbelegung, AC/DC-Tabelle) nicht gelesen; für den Emulator entbehrlich.
6. **DMA-Pfad**: Segmentnummernbildung bei DMA im P8000 (DMASYNC = ZBUSACK−, [P2b] §1.1) — die MMU
   übersetzt dort nur, wenn eine DMA-Einheit logische Adressen ausgibt; ob die P8000-DMA (WDC-Weg) das
   tut, ist **nicht** Teil dieser Quelle (nach [P2b]: Busmasterwechsel gibt die Treiber frei).
7. **Transkriptionsfehler** in [TB]: Satzreste in §5.2/5.3 (SUP bei „dazwischengeschobenen DMA-Operationen“)
   und das „leitoptimierte“ in §8.1.2 sind OCR-Reste; inhaltlich durch [Z] S. 565 abgedeckt.
