# Feinentwurf: K8025 ASS – Anschlußsteuerung Seriell

**Modul:** `core/cards/k8025/`  
**Dateien:** `k8025.h`, `k8025.cpp`  
**Dokumentation:** `doc/trascripted/Anschlußsteuerung K 8025.50 und K 8025.80.md`

## 1. Aufgabe

Die K8025 ist die serielle Schnittstellenkarte des A5120. Sie verbindet:
- Tastatur K7637 (IFSS, 9600 Baud, intern)
- Drucker (IFSS, 9600 Baud)
- DFÜ / Modem (V.24 und/oder IFSS, 50–9600 Baud, programmierbar)

---

## 2. Hardware-Zusammensetzung

```
K8025-Karte (Variante .50: V.24 + IFSS)
├── SIO A33 (Q 304) – DFÜ-SIO, Ports 50H–53H
│   ├── Kanal A: DFÜ/V.24 (X6), mit Steuerleitungen
│   └── Kanal B: DFÜ/IFSS (X5), ohne Steuerleitungen (DCDB = V107, s. §10)
├── SIO A32 (Q 304) – Drucker/Tastatur-SIO, Ports 5CH–5FH
│   ├── Kanal A: Tastatur K7637 (X4; laut Kartendoku Zusatzdrucker)  ← bestätigt
│   └── Kanal B: Hauptdrucker (IFSS, X3)
├── CTC A34 (Q 302) – Taktversorgung, Ports 58H–5BH
│   ├── Kanal 0: Takt beider Kanäle der A32 (fest; Drucker 9600 Baud)
│   ├── Kanal 1: Takt DFÜ/IFSS, nur mit Wickelverbindung X8–X9 (sonst ZRE-CTC K0)
│   └── Kanal 2: Takt DFÜ/V.24, nur mit Brücke W1:7 versetzt (sonst ZRE-CTC K0)
└── PIO A31 (Register A31) – Übertragungsparameter, Ports 54H–57H
    └── DIL-Schalter-Abbild (Baudrate, Format für DFÜ)
```

## 4. Klassen-Interface

```cpp
class K8025 : public BusDevice, public InterruptSlave {
public:
    struct A5120Config {
        uint8_t io_base = 0x50;       // Standard: 50H
    };

    K8025(K1520Bus& bus, const A5120Config& cfg = A5120Config{});

    // BusDevice: Ports 50H–5FH (16 Ports)
    uint8_t     ioRead(uint8_t port) override;
    void        ioWrite(uint8_t port, uint8_t data) override;
    const char* deviceName() const override { return "K8025"; }

    // InterruptSlave (interne Kette: SIO A33 → SIO A32 → CTC A34 → PIO A31)
    void    setIEI(bool iei) override;
    bool    getIEO() const override;
    bool    hasInterrupt() const override;
    uint8_t getVector() const override;

    // Tastatur-IFSS (SIO A32, Kanal A, X4)
    void    keyboardRxByte(uint8_t byte);   // Byte von K7637 injizieren
    bool    keyboardTxAvailable();          // Byte an Tastatur (LED-Steuerung)?
    uint8_t keyboardTxGet();

    // DFÜ-Schnittstelle (SIO A33, Kanal A)
    using SerialCallback = std::function<void(uint8_t)>;
    void    dfueRxByte(uint8_t byte);       // Byte vom Modem/Host injizieren
    bool    dfueTxAvailable();              // CPU hat Byte an DFÜ gesendet?
    uint8_t dfueTxGet();
    void    setDFUERxCallback(SerialCallback cb);

    // Drucker-Schnittstelle (SIO A32, Kanal B, X3)
    bool    printerTxAvailable();
    uint8_t printerTxGet();

    // CTC-Takt (einmal pro CPU-Step aus Machine-Loop aufrufen)
    void    clockTick();

    // Sub-Chip-Accessoren
    Z80SIO& sioA33() { return sio_dfue_; }
    Z80SIO& sioA32() { return sio_kbd_printer_; }
    Z80CTC& ctcA34() { return ctc_a34_; }

private:
    void updateInternalChain();  // IEI durch interne Kette propagieren

    A5120Config    cfg_;
    Z80SIO         sio_dfue_        {"K8025-SIO-A33"};  // Ports 50H–53H
    Z80SIO         sio_kbd_printer_ {"K8025-SIO-A32"};  // Ports 5CH–5FH
    Z80CTC         ctc_a34_         {"K8025-CTC-A34"};  // Ports 58H–5BH
    Z80PIO         pio_a31_         {"K8025-PIO-A31"};  // Ports 54H–57H
    bool           iei_in_  = false;
    SerialCallback dfue_rx_cb_;
};
```

## 5. Tastatur-Anbindung (K7637 → K8025 → K1520Bus)

### 5.1 Tastatur-Anschluss: SIO A32 Kanal A (X4)

Die Tastatur K7637 ist an Stecker **X4** angeschlossen, das ist **SIO A32, Kanal A** (Ports 5CH/5DH).

- SIO A32 Kanal A (5CH/5DH): Tastatur K7637 (IFSS, X4)
- SIO A32 Kanal B (5EH/5FH): Hauptdrucker (IFSS, X3)

### 5.2 Datenfluss

```
K7637::sendKeycode(0x41)          // 'A' getippt
    → IFSS-Bit-Stream (9600 Baud, 1+8+1)
    → K8025::keyboardRxByte(0x41) // direkte Injektion im Emulator
    → sio_kbd_printer_.channelA().rxByte(0x41)
    → SIO setzt RxRDY, löst Interrupt aus
    → Z80CPU: Interrupt-Handler bei SIO-Vektor
    → OS liest Port 5CH (SIO A32 Ch A Data) → 0x41
```

## 6. Baud-Rate-Konfiguration

Der CTC A34 generiert die Baud-Raten für beide SIO-Chips. Die ZC/TO-Ausgänge des CTC werden als Clock-Eingänge der SIO-Kanäle verwendet.

**Standard-Konfiguration A5120** (Transkription §2.3.1, §2.4, §3.1):
- CTC A34 Kanal 0 → beide Kanäle der A32 (Tastatur, Drucker; fest 9600 Baud)
- DFÜ/V.24 (A33-A) und DFÜ/IFSS (A33-B) → **ZRE-CTC Kanal 0** über ZC/TO des
  Rechnerbusses (Brücke W1:7 bzw. Wickelverbindung X7–X8, „gezeichnet“); versetzt
  CTC A34 Kanal 2 (V.24) bzw. Kanal 1 (IFSS, X8–X9)
- Die DIL-Schalter A41 geben die Baudrate nur als Wert für das BIOS vor (Register A31)

**DIL-Schalter A41 Emulation:**
Die Baud-Rate-Einstellung des DIL-Schalters wird als statische Konfiguration im Emulator gesetzt:

```cpp
struct A5120Config {
    uint32_t dfue_baud = 9600;    // Entspricht DIL-Schalter A41
    // weitere DIL-Parameter...
};
```

## 7. Interrupt-Verkettung

Die K8025 enthält drei interrupt-fähige Chips (SIO A33, SIO A32, CTC A34). Die interne Interrupt-Kette auf der K8025-Karte:

```
/IEI → SIO A33 → SIO A32 → CTC A34 → /IEO
```

Die K8025 als Ganzes ist Glied in der K1520-Bus-Interrupt-Kette.

## 8. V.24-Schnittstelle

Seit AP-S5 geht die V.24 (Stecker X6) wie alle einstellbaren Schnittstellen über einen
`SerialAnschluss` an den `SerialHub` der Maschine (Telnet/RFC 2217/Datei, §10 und
`doc/design/19_serielle_schnittstellen.md`).  Der ältere Rückrufweg bleibt als
Test-Unterbau:

```c
// C-API — Rückruf = Bytes, die der Gast SENDET; send = Byte in seinen Empfänger.
// Belegt ein Transport oder der Rx/Tx-Loop die Schnittstelle, gehen beide ins Leere.
k1520_serial_set_rx_cb(h, K1520_SERIAL_DFU, my_callback, ctx);
k1520_serial_send(h, K1520_SERIAL_DFU, 0x0D);  // CR an die DFÜ/V.24 des Gastes
```

## 9. Testbarkeit

```python
# tests/python/test_k8025.py
def test_keyboard_rx_triggers_interrupt(k8025_lib, k1520_bus):
    card = k8025_lib.k8025_create(k1520_bus)
    k8025_lib.k8025_keyboard_rx(card, 0x41)  # 'A' injizieren
    # SIO A33 Ch B müsste RxRDY setzen
    assert k8025_lib.k8025_has_interrupt(card)
    # Interrupt-Vektor lesen
    vec = k8025_lib.k8025_int_ack(card)
    assert vec != 0xFF

def test_printer_tx(k8025_lib, k1520_bus):
    received = []
    card = k8025_lib.k8025_create(k1520_bus)
    k8025_lib.k8025_set_printer_callback(card, lambda b: received.append(b))
    # Z80 schreibt 0x0D (CR) an Drucker-SIO
    k8025_lib.k8025_io_write(card, 0x5C, 0x0D)  # SIO A32 Ch A Data
    assert 0x0D in received
```

## 10. Schnittstellen nach außen (AP-S5, 2026-10-01)

Je einstellbarer Schnittstelle ein `SerialAnschluss` (`K8025::anschluss`), in dieser
Reihenfolge im `SerialHub` der `A5120Machine` angemeldet (= Index der C-ABI):

| i | Name | Stecker | SIO | Art | Taktquellen (Index 0 = gezeichnet) |
|---|------|---------|-----|-----|-------------------------------------|
| 0 | DFÜ/V.24 | X6 | A33-A | V.24 | ZRE-CTC K0 (W1:7) / CTC A34 K2 (W1:7 versetzt) |
| 1 | DFÜ/IFSS | X5 | A33-B | IFSS | ZRE-CTC K0 (X7–X8) / CTC A34 K1 (X8–X9) |
| 2 | Drucker | X3 | A32-B | IFSS | fest CTC A34 K0 |
| — | Tastatur K7637 | X4 | A32-A | — | fest, `K8025::TASTATUR_NAME`, nicht einstellbar |

**Leitungen** (Transkription §2.3.2, Gatter A23): /CTSA = V106 ∧ V107, /DCDA = V109 ∧
V107, und V107 zusätzlich allein an **DCDB** („Betriebsbereitschaft allein abfragbar“);
RTSA → V105, DTRA → V108.  V125/V111/V113–V115 werden nicht nachgebildet.  Die übrigen
/CTS- und /DCD-Eingänge (CTSB, CTS/DCD der A32) bleiben **inaktiv** wie seit AP-S3 — der
Stromlaufplan der K8025 liegt nicht vor, die Betriebsdokumentation beschreibt für die
IFSS-Kanäle keine Steuerleitungen; der Gast sieht damit dasselbe RR0 wie vor AP-S5.
DCDB folgt V107 der V.24 nur, solange dort etwas angeschlossen ist (ohne Verbindung
inaktiv — ebenfalls unverändert).

**Takt der ZRE-CTC K0:** `K8025::setzeZreTakt` (die Maschine gibt
`zre_.ctc().teilerTakte(0)`).  Dieselbe Quelle ist die Eingangsperiode an CLK/TRG0–3 der
CTC A34 — im Emulator liegt ZC/TO0 der ZRE schon seit jeher über den Koppelbus an allen
vier Eingängen der A34 (`A5120Machine::wireBackplane`).

**Alter Unterbau:** `setAbnehmer(s, cb)`/`einspeisen(s, b)` (dahinter
`A5120Machine::setDFUECallback`/`dfueSend` = DFÜ/V.24, `setPrinterCallback`/
`printerSend` = Drucker; `setDFUERxCallback` = Abnehmer der DFÜ/V.24 — bis AP-S5 wurde
dieser Rückruf gespeichert, aber nie gerufen).  Ein gesetzter Abnehmer bekommt jedes
Byte in seiner Zeichenzeit (der Wandler taktet), aber nur, solange weder Transport noch
Loop den Stecker belegen (`SerialAnschluss::leitungBelegt`).

**Verhaltensänderung für den Gast:** Bis AP-S5 holte niemand die Sendebytes von A33 und
A32-B ab — ein Gast, der dort sendete, stand mit vollem Sendepuffer.  Jetzt nimmt der
Wandler sie in ihrer Zeichenzeit ab (unverbunden: sie verfallen, „Kabel ab“, Entwurf 19
§6.1).  Die Tastatur (A32-A) ist davon nicht berührt.

Wächter: `K8025Seriell.*` (Kanalzuordnung, Taktquelle, V.24-Verknüpfungen, Tastatur
unberührt, alter Unterbau), `A5120Seriell.GastSendetUeberDfueV24InEineDatei`.
